日期：2026-10-21。分支 `feat/lavender-scrapbook-local`。

## 一、现状核对

上一份任务里已经把「实验室」从「关于」拆出来了（枚举 `SettingsPage.Lab` + `LabPage()` + 独立路由）。这一版按你补充的规格补了**页面标题、顶部说明、卡片式入口（带实验性标识）**，其余保持。

## 二、实验室页面

- 标题：**Cleos 实验室**（枚举 title 与设置首页入口都改了）
- 顶部说明：原文照录 ——「这里收录正在开发或验证中的实验功能。部分功能可能存在兼容性问题，需要额外授权，不影响正常聊天功能。」
- 三张卡片，每张：**功能名 + 「实验性」小标签 + 一句话说明 + 右侧箭头**
- 三张卡片放在一张 `ListCard`（设置页现成的玻璃卡片）里，行间用 `RowDivider`；没有为实验室单独做一套 UI
- 紫雾手账下走纸面样式，原版主题下走玻璃样式（截图 02 / 03）

## 三、三个功能（全部复用原实现）

| 功能 | 复用 | 迁移方式 |
|---|---|---|
| 虚拟屏探针 | `VirtualScreenProbeActivity` | 原 Activity 一行没改，只把入口从「关于」搬到实验室 |
| 一起看（验证版） | `WatchTogetherActivity` | 同上；权限申请、状态、停止入口都是原来的 |
| HTML 渲染自检 | `HtmlSelfTestDialog` | 同一个 composable，实验室里点开、关掉回到实验室 |

没有复制对话框、没有第二套状态管理、没有重写探针逻辑。

## 四、导航与返回

- 设置首页 → Cleos 实验室 → 子功能：`startActivity` / Dialog，返回栈天然正确
- 三个功能实测：进入 → 返回 → **回到实验室页**（截图 05），不是退出 App
- 实验室页再返回 → 设置首页；再返回 → 聊天页
- 没有死循环

## 七、未验证 / 未做

- **一起看的授权弹窗没有真的走一遍**：只验证了页面能打开、状态显示「未开始」；点「开始一起看」会弹系统投屏授权，这一步涉及系统级弹窗，自动化点击不稳，**没有做**。权限拒绝/撤销/资源释放这条路径也没有实测。
- 虚拟屏探针只验证了入口和按钮存在，**没有逐个点「创建虚拟屏 / 启动抖音」等按钮**（那会真的拉起抖音、影响当前测试）。
- 实验室还没有加任何新项目（按你的要求，不摆空按钮）。
