## 优先级一：修复已在源码确认的问题
1. TicTacToeScreen.taMove 目前捕获旧 after，收到回复就直接 game = after.play(...)；请求期间“重开”和“换一个 TA”仍可操作，因此旧回复会覆盖新棋局。为每局设唯一 sessionId、递增 revision，为每次请求设 requestId，落子/错误提示/finally 清 busy 前均核对归属。取消与 token 失效一起做，不能仅依赖取消网络。
2. 重试按钮没有 disabled，taMove 自身也没有入口防重。请求期间禁用重试，并在状态协调层原子认领一次请求；当前必须是 O 回合、未结束、没有待处理请求。双击、页面重入不能触发双请求。
3. GameAi 创建独立 OkHttpClient + ChatClient(http)，绕开 AppContainer.chatClient 的诊断和用量回调。改用现有共享客户端，为每次实际调用传 UsageTag，归属受邀 TA，purpose 可为 game_tic_tac_toe。非法动作的自动重试也必须分别计入实际用量。
4. askMove 未传入受邀 TA，prompt 没有其角色信息。目前只是一个通用模型在下棋。传 taId，从数据库读取真实角色，加入适量名字/设定（不需要整段聊天历史）；角色被删或身份改变要清楚反馈。当前源码是统一 Feature.Chat 路由，沿用这条路由并如实显示，不声称已有每角色独立模型绑定；遵守 Provider 协议检查、temperature/maxTokens 等现有配置。
5. parseMove 扫描全文所有数字，可能把“不能下 4，考虑 0 或 2”中的任一数字当落子。改为严格整段单一 0..8，或一种明确定义且严格解析的结构化格式。负数、多候选、解释文字、越界、占用格、空输出均拒绝；更新原有“数字提取”测试，避免保留宽松行为。
6. runCatching 会捕获 CancellationException；取消必须重新抛出，不应变成普通 Failed。增加明确超时、输出长度上限。保持有限非法动作重试，不对网络/配置失败自动重复付费；用类型区分失败，避免靠中文错误前缀判断是否可重试。明确 attempts 是总调用次数还是追加次数。
7. 同步修正屏幕顶部仍写“P0-A 本地模拟”的过时注释，清理不再使用的 import；UI 与实际模型模式一致。

## 优先级二：棋局持久化与恢复
- 保存唯一局 ID、游戏类型、受邀 TA 身份、棋盘/有序历史、回合、状态、revision；本地规则是唯一权威，模型只给行动。
- 使用项目现有 Room 习惯或独立游戏 Room 存储，选择兼容、可测的最小变更。若改主库，必须带非破坏性迁移及 schema；不得覆盖 DSH 其他尚未推送的迁移。
- 先把用户 X 落子保存，再请求 O；O 验证成功后保存。退出、旋转、杀进程、重启可恢复，不得仅靠 remember/rememberSaveable。
- 请求可以选择离页取消，或 App 作用域继续，选一种并在报告说明；无论哪种都不能被旧页面协程覆盖。
- 进程重启不会有原来的网络请求：清掉/转为“已中断，可继续”，保留 O 回合；打开页面不自动重试付费，提供显式“继续 TA 回合”。
- 重开/换 TA 时先使旧请求失效，再建立新局；迟到结果不能写盘。
- 防止备份导入或删除重建角色后 ID 复用误认 TA（使用稳定身份或创建标识）。若游戏不纳入 ZIP 备份，界面如实说明，恢复/撤销恢复时处理旧棋局与待处理任务；不要默默把旧局绑到新角色。
- 存档损坏时保留原始记录、给出清楚恢复/重置选项，不悄悄清空其他用户数据。
