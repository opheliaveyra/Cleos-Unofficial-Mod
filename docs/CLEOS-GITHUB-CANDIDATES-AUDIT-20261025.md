## 候选 A：mem0ai/mem0
仓库：https://github.com/mem0ai/mem0
许可证：Apache-2.0（项目 README 所述，复用代码前仍核对实际文件）。
借鉴：会话/用户/角色层级，事实提取，带时间的记忆，语义+关键词+实体融合召回；保留原始出处。
不建议：直接依赖 Mem0 云服务或原样嵌入 Python 服务端。其官网 README 的高分 benchmark 对应托管平台专有优化，不能作为本地 Cleos 的效果承诺。
建议增量：
1. 盘点现有记忆表、摘要任务、提示词注入点和召回路径。
2. 增加“候选记忆 → 去重/冲突检测 → 用户可审核 → 按角色写入”的可选流程。
3. 检索先做本地关键词+时间+角色过滤基线，量化效果后再考虑 embedding。
4. 注入 Token 上限；统计后台记忆任务的实际 token 与失败重试。
验收：角色隔离；不同日期冲突可区分；关闭功能后行为不变；备份恢复；中文样例；长会话 token 不失控。

## 候选 B：主动消息的触发决策
前次对话提到 revive-companion，但本轮没有完成仓库身份、许可证、源码核验，**不得按已确认第三方代码引入**。
先审计 Cleos 现有主动搭话的调度与通知实现，重点增量：
- 冷却期、静默时段、用户最近互动与重复话题过滤；
- “有未完话题/日程事件”与“仅到定时”分开；

验收：不骚扰；无网络不重复轰炸；重启不重复触发；关闭后无后台推送。
