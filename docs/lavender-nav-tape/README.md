# 导航栏胶带交互（可揭起 / 拖动 / 重新贴合）

日期：2026-10-21。只改了 `ScrapbookTabBar`，没有重建导航系统。

## 实现

| 动作 | 实现 |
|---|---|
| 长按揭起 | `detectDragGesturesAfterLongPress`，只有按在**当前选中那格**上才揭，按别处不拦 |
| 揭起视觉 | `graphicsLayer`：放大 6%、转 -2.5°，`animateFloatAsState` 180ms |
| 拖动 | 胶带仍画在自己那一格里（静止位置本来就是对的），拖动时只叠一个 `translationX` |
| 范围限制 | 位移钳到「最左格中心 ~ 最右格中心」，拖不出导航栏 |
| 目标反馈 | 手指经过的格子图标变紫，但不提前切页 |
| 松手贴合 | `tapeShift.animateTo(目标位移, 170ms)` 先滑过去，再切页面、复位 |
| 取消 | `onDragCancel` 平滑回原格，不切页 |
| 普通点击 | 原来的 `selectable` 逻辑没动 |

关键决定：**胶带不搬到独立覆盖层**。第一版试过整条导航栏上单独一层飘着的胶带，
纵向位置怎么算都对不上（导航栏底部还有安全区 inset）；改成「留在格子里 + translationX」
后静止位置不用算，只有拖动时才有偏移。

## 顺手改的

胶带不透明度 28% → 46%。28% 的淡紫放在纸带上几乎看不见（调试时用纯红方块才确认到绘制是好的）。

# 第二轮：修普通点击被吞掉

## 问题

普通点击完全失效，只能长按拖胶带切页。

## 原因

拖动检测挂在一个**盖住整条导航栏的 Box** 上（`Box(fillMaxSize().pointerInput { detectDragGesturesAfterLongPress }) `），
它压在子元素上面，轻点的 down/up 序列被它先接走，`selectable` 收不到。

## 修法

把 `pointerInput` 从覆盖层挪到 **Row 自己身上**（也就是 `selectable` 的父层）。

这样事件分发顺序变成：
- 轻点 → 子元素的 `selectable` 先处理 → 正常切页
- 长按 → 子元素没响应（selectable 不处理长按），父层的长按检测接手 → 拖动

## 验证（荣耀 YAL-AL50）

| 项 | 结果 | 证据 |
|---|---|---|
| 轻点「待办」→ 切到待办，胶带跟过去 | ✅ | 05 |
| 轻点「聊天」→ 切回聊天 | ✅ | 05 之后 |
| 长按 + 拖动仍然可用 | ✅ | 06（从聊天拖到右侧，落在相邻格、页面同步切） |

> adb 模拟的拖动每次 MOVE 都是离散跳点，落点和手指终点会差一格；真机连续拖动不会。这不是代码问题。

## 没动的

- 揭起/贴合动画没加也没改（按你的要求先停在这里）
- 原生主题完全不进这个函数
