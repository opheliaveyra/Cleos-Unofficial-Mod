# Cleos UI 规范：壁纸不能破坏可读性与控件可发现性

> 背景由用户决定（自定义壁纸），界面必须**在任意壁纸上都读得清、点得到**。
> 这条规则优先于视觉效果；**不允许通过限制用户选择壁纸来规避**。

## 1. 硬性要求

| 类别 | 要求 |
|---|---|
| 正文文字 | 与紧邻背景的对比度 ≥ **4.5:1**（WCAG AA）；大字号/图标 ≥ 3:1 |
| 文字承载面（卡片、气泡） | **不靠壁纸凑巧安静**：承载正文的玻璃/卡片 tint 不透明度 **≥ 0.6**（见 `GlassStyle` 注释里的同一原则） |
| 关键操作（添加、删除、发送、保存、开关） | 必须**有可见的控件形状**（实心或高不透明底 + 边框），不能是"一行透明小字" |
| 卡片外的裸文字（页面说明、状态、错误） | 必须有底衬（卡片/半透明衬底/描边），不能直接压在壁纸上 |
| 只承载图标/大字的 chrome（顶栏、tab） | 可以更透明（0.3+），但图标颜色必须与背景形成 ≥3:1 |

## 2. 已确认的反例（0.1.8x 系列）

- `Chip` 用 `content.copy(alpha = 0.07f)` 做底：在插画壁纸上等于没有底，像"糊掉的一行字"。
- 添加按钮只有文字、无形状：用户要靠猜它能不能点（0.1.87→0.1.89 连续被指出）。
- `PageNote` / `MessageLine` 直接画在壁纸上：复杂壁纸下说明文字发灰、看不清。

## 3. 回归测试（每次 UI 改动）

**用三类壁纸各过一遍关键页面**，截图留档：

1. **纯黑**（最深）：检查浅色文字、透明控件是否还看得见。
2. **纯白**（最亮）：检查浅色文字是否会消失、玻璃卡片是否发灰。
3. **高饱和 + 明暗混合**（比如彩色插画、渐变）：检查纹理是否把文字/控件"吃掉"。

**必查页面**：设置首页、服务商/模型配置（列表长、控件多）、聊天页、小游戏（棋盘）、关于页（实验入口）、对话/编辑弹窗。

**检查方法**：截图后放大看——文字是否与背景"混"在一起；按钮是否能一眼看出是按钮；禁用/可用状态是否还能区分。

## 4. 排查清单（代码层）

- [ ] 搜索 `alpha = 0.0` / `alpha = 0.1` 的**文字背景**使用，逐个判断是否承载正文或关键操作。
- [ ] `TextButton` 默认无底：用作**主操作**时必须换实心按钮。
- [ ] 卡片外文字（`PageNote`、`MessageLine`、空状态提示）一律套底衬。
- [ ] 玻璃卡片 tint 不得低于 0.6（`GlassStyle` 注释里的下限）。
- [ ] 新增"添加/创建"入口：按 0.1.87 约定放页面顶部，且是**实心按钮**（0.1.89 起的样式）。
